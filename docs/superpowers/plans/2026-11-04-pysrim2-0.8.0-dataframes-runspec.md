# pysrim2 0.8.0 — DataFrames, run.yaml and Cascade Export Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every SRIM output is available as a pandas DataFrame (incl. per-ion RANGE_3D, EXYZ, backscattered/transmitted/sputtered atoms and full cascades), runs are described by an editable `run.yaml` that regenerates TRIM.IN and records seed + provenance, results export to Parquet/HDF5/CSV with that metadata, and the notebooks, examples, skill and docs use the new API — released as 0.8.0.

**Architecture:** Parsers stay in `srim/output.py` (split into a package `srim/output/` only if a file grows beyond ~600 lines — Task 1 decides). Each parser class gains a `df` property; `Results` gains `to_dataframes()` and export methods. A new `srim/spec.py` holds the run spec dataclasses and YAML round-trip; `TRIM` gains `to_spec()/from_spec()`. CLI gains `pysrim2 run` and `pysrim2 import`.

**Tech Stack:** Python 3.11–3.15, pandas (already a dependency), pyyaml, optional pyarrow (`[parquet]`) and PyTables (`[hdf5]`), uv, pytest, real-SRIM integration tests (marker `srim`).

**Spec:** `docs/superpowers/specs/2026-11-03-pysrim2-design.md` (New API: DataFrames, Run spec file `run.yaml`, Cascade export; Release roadmap 0.8.0)

## Global Constraints

- Distribution `pysrim2`, import `srim`, Python ≥ 3.11. No new *required* dependencies: Parquet needs `pysrim2[parquet]` (pyarrow), HDF5 needs `pysrim2[hdf5]` (tables); missing extras raise `ImportError` naming the extra.
- DataFrame column names are snake_case with the unit as suffix: `depth_A`, `x_A`, `y_A`, `z_A`, `energy_eV`, `energy_keV`, `ions_per_A` … (SRIM's native units; no silent unit changes). Document every column.
- Existing attribute APIs (`.depth`, `.ions`, …) keep working unchanged.
- `run.yaml` schema version `1`; `spec:` (everything needed to regenerate TRIM.IN, units in key names) and `provenance:` (informational) sections; TRIM.IN written from a spec must be byte-identical to TRIM.IN written by the equivalent `TRIM(...)` object.
- If no seed is given, pysrim2 picks one and records it in `run.yaml` provenance and spec.
- Fork-commit rules from Plan 1 (cherry-pick with `-x` where a fork commit is reused verbatim; otherwise our own commit with `Co-authored-by:`). EXYZ parser credit: philis-johan (547780e).
- Work on `main`; small logical commits; CHANGELOG line per user-visible change; CI (Linux, Windows, container) green; macOS matrix may be verified locally if GitHub runners stall.
- First step of Task 1: `uv version 0.8.0.dev0`.

## Review Focus

1. Very large COLLISON.txt / EXYZ.txt (hundreds of MB) — parsing must stream (no full-file read into memory for cascade export) and Parquet export must write in chunks. (Task 6)
2. SRIM output files written on comma-decimal Windows locales — every new parser must go through `_to_float` / the comma-safe table reader. (Tasks 2–6)
3. Output files that are missing because a calculation mode doesn't produce them (e.g. RANGE_3D without `ranges=1`) — `Results` attributes are `None`, `to_dataframes()` skips them, no exception. (Tasks 2–4)
4. `run.yaml` edited by hand with a typo or wrong unit key — clear validation error naming the key, not a KeyError deep inside. (Task 7)
5. A seed-recorded rerun on the same machine/backend gives identical per-ion results; across platforms identity is reported, not required (user decision). (Task 8)
