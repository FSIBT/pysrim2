# pysrim2 0.13.0 plan 2: the app side of the agent — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `pysrim2 mcp` drives the open pysrim2 app: agent edits land in the tabs and in undo, runs show in Progress, plots in Results; the app shows an Agent activity panel, asks the user in a dialog, helps connect agents, and offers live results during a single run.

**Architecture:** The app listens on a per-user local socket (`QLocalServer`) while it runs and writes a private discovery file. `srim/mcp/app_client.py` (Qt-free) connects to it and implements plan 1's `Backend` protocol by sending JSON-line requests; `server.choose_backend` tries the app first on every call. In the app, `srim/app/agent_server.py` accepts connections and hands each request to `srim/app/agent_backend.py`, which acts through the same code paths as the tabs (`DocumentModel.edit`, `RunController`, the Results tab). Results, tables and plot images are still computed in the `pysrim2 mcp` process from the run folder (plan 1's `srim/mcp/results.py`); the app is only told to show the plot.

**Tech Stack:** PySide6 (`QLocalServer`, `QLocalSocket`, `QDockWidget`), pytest-qt (offscreen), plan 1's `srim.mcp`.

**Spec:** `docs/superpowers/specs/2026-11-15-pysrim2-0.13.0-agent-mcp-design.md`. Requires plan 1 (`2026-11-15-pysrim2-0.13.0-plan1-mcp-server.md`) to be done.

## Global Constraints

- All plan 1 constraints hold.
- The no-Qt rule: `srim/mcp/*` stays Qt-free; only the new `srim/app/agent_*.py`, `approval_dialog.py`, `connect_dialog.py` and `agent_settings_dialog.py` import PySide6.
- The socket is private to the user (`QLocalServer.SocketOption.UserAccessOption`); the discovery file is `data_dir()/app/agent.json`, mode 0o600 on POSIX; the token (32 random bytes, hex) is never on a command line or in a log. No TCP listener.
- Every agent edit goes through `DocumentModel.edit(fn, label=...)` and is exactly one undo step labelled `"agent: <summary>"`. An edit while a run is going is refused with `LOCKED_TEXT`.
- The app never runs admin installer steps (as in 0.12.0).
- Ask-first answers in app mode come from a dialog in the window; it never blocks the GUI (`open()`, never `exec()`); no answer within **120 s** counts as `"timed out"`.
- Live updates: off by default; when on, a single run is split into **10** batches (`batch_ions = ceil(number_ions / 10)`, at least 1) with seeds from `derive_seed`; the option is saved in `run.yaml` so a scripted run reproduces it.
- Qt tests run offscreen with fake checks, steps and runners; no real agent, SRIM, network or notebook tool.

## Review Focus

- **The app crashed and left `agent.json` behind:** `pysrim2 mcp` treats a failed connection or a wrong token as "no app" and works headless; the next app start overwrites the file — pinned in Task 1 and Task 3.
- **The user edits while the agent edits:** both go into one history in order; undo of the agent step restores the state before it, not the user's later edit — pinned in Task 2.
- **The agent asks for something while a confirm dialog is already open:** requests queue, one dialog at a time, each answered separately — pinned in Task 5.
- **The app is closed mid-session:** the next tool call works headless (and says so in `mode`); a run the app started was the app's and stops with it, as in 0.12.0 — pinned in Task 9.
- **Live updates on a scan, a precision target or a binned beam:** the option is greyed out for a scan and ignored for runs that are batched anyway; turning it on never changes a run without it — pinned in Task 8.

**Interfaces:**
- Produces:
  - `discovery.discovery_path() -> Path` (`data_dir()/"app"/"agent.json"`); `AppEndpoint` (frozen dataclass: `socket: str` (the `QLocalServer.fullServerName()`), `token: str`, `pid: int`, `version: str`); `write_endpoint(endpoint) -> None` (atomic: temporary file + `os.replace`, private mode); `read_endpoint() -> AppEndpoint | None` (None for missing or broken); `remove_endpoint(token: str) -> None` (removes only a file holding that token).
  - `protocol.encode(message: dict) -> bytes` (one UTF-8 JSON line); `LineReader` with `feed(data: bytes) -> list[dict]` (keeps a partial line; a line over 16 MiB raises `ProtocolError`).
  - Messages: hello `{"hello": {"token", "client", "protocol": 1}}` → `{"hello": {"ok": true, "version"}}` or `{"hello": {"ok": false, "error"}}`; request `{"id": int, "method": str, "params": dict}`; reply `{"id", "result": …}` or `{"id", "error": {"type": "BackendError" | "NeedsApp", "message": str}}`.
  - `socket_connect(name: str, timeout: float) -> BinaryIO-like` — POSIX: `socket.AF_UNIX` to the path; Windows: `open(rf"\\.\pipe\{name}", "r+b", buffering=0)` when `name` is not already a full pipe path. Raises `OSError` on failure.

### Task 3: The app's agent socket server

**Files:**
- Create: `srim/app/agent_server.py`
- Modify: `srim/app/window.py` (start on open when `settings.agent_socket`, stop in `stop_background`/close)
- Test: `tests/app/test_agent_server.py`

**Interfaces:**
- Consumes: Task 1; `AgentBackend` (Task 4) — this task uses a stand-in object with a `handle(method, params) -> Any | Deferred` method.
- Produces:
  - `class Deferred(QObject)` with `resolve(value)`, `reject(error: BackendError)` and a `done` signal — a handler may return one for an answer that comes later (a dialog, a load in a thread).
  - `class AgentServer(QObject)`: `__init__(handler, client_seen: Callable[[str], None], parent=None)`; `start() -> None` (listens on `f"pysrim2-{getpass.getuser()}-{secrets.token_hex(4)}"` with `UserAccessOption`, writes the endpoint); `stop() -> None` (closes the server and all sockets, `remove_endpoint(token)`); `listening -> bool`; signal `client_connected(str)` (the client name from hello). Requests on one connection are answered in order; requests from several connections are handled one at a time on the GUI thread. An unknown method replies `BackendError("unknown method …")`; an exception in a handler replies its text as `BackendError` and is logged, never crashing the app. A connection whose first line is not a hello with the right token is closed.
