# pysrim2 0.12.1 Notebooks Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The desktop app's Notebook menu: Start marimo (the default) and Start Jupyter create a starter notebook in the run folder and show it in an embedded web view. A banner says when the run has new results, Reload re-runs the loading cell, marimo can follow the run, and Export to PDF writes the notebook as a PDF.

**Architecture:** A library module `srim/notebook.py` reads a run folder, finished or not, for notebooks. The app's run-folder reading moves there, so the app and the notebooks read results the same way. A Qt-free module `srim/app/notebooks.py` covers the rest outside Qt:
- the starter templates, shipped in `srim/data/notebooks/`;
- the server command and URL;
- a `subprocess`-based `NotebookServer` (start, wait until ready, stop, log);
- the PDF commands.

A Qt module `srim/app/notebook_tab.py` shows the server in a `QWebEngineView`, with the banner and the buttons.

The notebook server always runs as its own process (`sys.executable -m marimo …` or `-m jupyterlab`). It reads the run folder and never touches the simulation.

**Tech Stack:** Python ≥ 3.11, PySide6 (Essentials plus Addons for QtWebEngine), marimo ≥ 0.19.7, JupyterLab, nbconvert WebPDF (Chromium through playwright), pytest, pytest-qt (offscreen).

**Spec:** `docs/superpowers/specs/2026-11-06-pysrim2-0.12.0-desktop-app-design.md` (goal 8; stage "0.12.x: notebooks"; constraints; "Calls made after the builder check": the starter template, the reload banner, marimo "follow" mechanics and PDF tooling are Claude's calls, decided in this plan)

## Global Constraints

- Spec goal 8: "Menu entries **Start marimo** (default) and **Start Jupyter** create a starter notebook in the run folder (first cell loads the current results, plus an example plot) and open it in an embedded web view. The notebook server runs in its own process, separate from the simulation; it reads the run folder. During a long run what the notebook loaded is a snapshot: a banner says when new results exist and reloading re-runs the loading cell; marimo additionally gets a "follow the run" switch that re-runs the loading cell and its dependents every N seconds. Notebooks are saved with the run. Notebook export to PDF: marimo's own export; Jupyter's needs LaTeX or a headless browser, offered as an optional setup step."
- Spec constraint: "the notebook tools (marimo; Jupyter optional) come with the 0.12.x notebook feature. `import srim` and the CLI never import Qt."
- Spec constraint: "The app works without network access once installed (except docs links and the agent)." The servers bind `127.0.0.1` only.
- AGENTS.md rules apply. The no-Qt rule: `tests/test_no_qt.py` gets every new Qt-free module, and a Qt-free module must never import a `PySide6` submodule, not even through `importlib.util.find_spec("PySide6.…")`, which imports `PySide6`. Also:
  - the document rule;
  - threads through `run_in_thread`;
  - one runner (`run_steps`);
  - wine and SRIM output in temporary files, not pipes;
  - never `uv run --active` or `uv sync --active`.
- Python 3.15: the app is not offered there, so the notebook extras carry the same `python_version < '3.15'` marker on their Qt packages.
- Every user-visible change gets a CHANGELOG line under `## [Unreleased]`. Conventional commits, with explicit paths.
- The servers' tokens never appear on a command line. marimo gets `--token-password-file`, and Jupyter gets the `JUPYTER_TOKEN` environment variable.

## Decisions (Claude's calls under the spec, listed for review)

- **Extras:**
  - `notebook = ["marimo>=0.19.7", "PySide6-Addons>=6.8; python_version < '3.15'"]`
  - `jupyter = ["jupyterlab>=4", "PySide6-Addons>=6.8; python_version < '3.15'"]`
  - `pdf = ["nbformat", "nbconvert[webpdf]>=7"]`
- **Install components** (in `srim/installer/notebook.py`, not in `default_components`):
  - `notebook`
  - `jupyter`
  - `notebook-pdf`: the `pdf` extra, then `python -m playwright install chromium` (a download, not an admin step).
  - Each installs its extra exactly as `app` does: `uv tool install --reinstall` with the existing extras, `pip`/`uv pip` at the pinned version, or the `uv sync --extra <name>` hint for a checkout.
- **Notebook files:** `<run folder>/notebook.py` (marimo) and `<run folder>/notebook.ipynb` (Jupyter). An existing file is opened, never overwritten. The app's own files go in `<run folder>/.pysrim2-notebook/`: `reload` (touched by Reload), `loaded.json` (written by the loading cell: `{"points": <n points with outputs>, "finished": <bool>}`), `token` (mode 0600) and `server.log`.
- **Banner:** the app compares `srim.notebook.results_count(folder)` with `loaded_count(folder)` while the Notebook tab is visible, every `refresh_seconds`, in a thread. It shows "New results since the notebook loaded them." when the current count is greater, or when the run has finished since.
- **Reload:**
  - marimo: Reload touches `.pysrim2-notebook/reload`. The loading cell reads it through `mo.watch.file(...)`, so marimo re-runs the cell and its dependents.
  - Jupyter: the banner adds "Run the first cell again to load them." The app does not drive the Jupyter kernel.
- **Follow the run (marimo only):** a `mo.ui.refresh(options=["5s", "10s", "30s", "1m"], label="Follow the run")` element in the starter. The loading cell references it, so choosing an interval re-runs the loading cell every N seconds.
- **One notebook per window at a time.** Starting another one, or one for a different run folder, asks whether to stop the running one. Closing the window or quitting stops the server: terminate, then kill after 5 s.
- **Embedded view:** a "Notebook" tab, added to the window's tabs when a notebook starts and removed when it stops. Its toolbar has Reload, Open in browser, Export to PDF… and Stop notebook.
  - `QtWebEngineWidgets` must be imported before the `QApplication` exists. `main.py` imports it when it is installed and sets `Qt.AA_ShareOpenGLContexts`.
  - Without it, the start entries are greyed with the install hint.
- **Greyed entries:**
  - Start marimo without marimo: "Install with: pysrim2 install notebook".
  - Start Jupyter without jupyterlab: "Install with: pysrim2 install jupyter".
  - Export without nbconvert or playwright: "Install with: pysrim2 install notebook-pdf".
  - No run folder yet: "Run the setup or open a run folder first".
  - The app installs nothing itself here.
- **Timeouts:** server ready 60 s (polling every 0.25 s), PDF export 600 s. The log tail shown on a failure is the last 20 lines.
- No gallery screenshot: a web view cannot be grabbed reliably on the offscreen platform.

## Review Focus

1. **The server does not come up** (port taken, a broken marimo, a crash). Expected: no hang. After at most 60 s, or as soon as the process exits, the user gets a message with the log tail, and the menu works again. Pinned in Task 3 (`test_a_server_that_exits_is_reported_with_its_log_tail`, `test_a_server_that_never_answers_times_out`).
2. **The window closes or the app quits with a server running.** Expected: the server process is gone afterwards, with no orphan. Pinned in Task 4 (`test_closing_the_window_stops_the_server`).
3. **A notebook already exists in the run folder** (the user edited it). Expected: it is opened as it is, never overwritten. Pinned in Task 2 (`test_an_existing_notebook_is_never_overwritten`).
4. **A notebook started during a run.** Expected: it loads the points finished so far, and the banner appears when more finish. Pinned in Task 1 (`test_an_unfinished_folder_loads_the_points_with_outputs`) and Task 4 (`test_the_banner_appears_when_more_points_have_outputs`).
5. **A run folder with spaces and non-ASCII characters.** Expected: the server, URL and PDF export still work, because commands are lists and URL paths are quoted. Pinned in Task 3 (`test_commands_and_urls_handle_spaces_and_non_ascii`).

  - `free_port() -> int`
  - `server_command(kind, path: Path, port: int, token_file: Path) -> list[str]`:
    - marimo: `[sys.executable, "-m", "marimo", "edit", str(path), "--headless", "--host", "127.0.0.1", "--port", str(port), "--token-password-file", str(token_file), "--skip-update-check"]`
    - Jupyter: `[sys.executable, "-m", "jupyterlab", "--no-browser", "--ip=127.0.0.1", f"--port={port}", "--ServerApp.port_retries=0", f"--ServerApp.root_dir={path.parent}"]`

  - `notebook_url(kind, path, port, token) -> str`:
    - marimo: `http://127.0.0.1:{port}/?access_token={quote(token)}`
    - Jupyter: `http://127.0.0.1:{port}/lab/tree/{quote(path.name)}?token={quote(token)}`
  - `class NotebookServerError(RuntimeError)`
  - `class NotebookServer`: `__init__(kind, path, command_for=server_command)`. Attributes `.url`, `.process` and `.log_path` (`NOTEBOOK_DIR/server.log`). Methods:
    - `start() -> None`: writes the token file with mode 0600 and sends the output to `log_path`, not a pipe. Jupyter gets `JUPYTER_TOKEN` in the child's environment only.
    - `wait_ready(timeout=READY_SECONDS) -> None`: any HTTP answer with status < 500 counts. It raises `NotebookServerError` with the log tail when the process exits or the time runs out.
    - `stop(grace=5.0) -> None`: terminate, then kill; idempotent.
    - `running -> bool`, `log_tail(lines=LOG_LINES) -> str`
