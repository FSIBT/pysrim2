# pysrim2 0.12.0, plan 3: scans, running, progress, results, saving and recent runs — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** In `pysrim2 app` a user defines a scan in a Scan tab, starts a single run or a scan (with a parallel prompt for long runs), watches it in the Progress tab, looks at and exports plots in the Results tab, saves the results in the library's formats, and reopens earlier setups and runs from a Recent menu. After this plan the app covers the 0.12.0 goals (1–7, 9, 10, 12).

**Architecture:** Every run, single or scan, is a `Scan` run by the library's `run_scan` in a background thread of the app (the SRIM work happens in its worker processes or containers). A single run is a one-point scan that keeps the spec's own seed (a small new library option, `keep_seed`), so its outputs are the same as `pysrim2 run` of the same `run.yaml`. The executor's events feed the existing Qt-free `ScanState` (the 0.9.0 dashboard's model), which the Progress tab draws. Results are read from the run folder with the library's readers; the Results tab draws plots from a Qt-free catalogue (`srim/app/plots.py`) whose entries say which outputs they need. The scan definition lives in the document as the app-only key `_scan`, the plain `scan:` section of `run.yaml`.

**Tech Stack:** Python ≥ 3.11, PySide6-Essentials ≥ 6.8, matplotlib (`backend_qtagg`, `NavigationToolbar2QT`), the existing `srim.scan` executor and events, `srim.ui.tui.state.ScanState`, `srim.export`, pytest-qt on the `offscreen` platform.

**Spec:** `docs/superpowers/specs/2026-11-06-pysrim2-0.12.0-desktop-app-design.md` (goals 4 "after a run the sampled values are drawn on top", 5, 6, 7, 9, 10; "Calls made after the builder check": where things run, source of truth, undo and editing during runs, recent runs, settings and user data, docs; "Decided by Arun": the Scan tab, 2026-11-12). Plans 1 and 2 are merged; this plan builds on their window, document, status bar and editor protocol.

## Global Constraints

- Everything from plans 1 and 2 still holds: `import srim`, `srim.cli` and every command except `pysrim2 app` never import PySide6; Qt tests live in `tests/app/`, skip without PySide6 or pytest-qt, use the offscreen platform and bounded waits; the app validates through the library only and adds no physics.
- Qt-free modules added here: `srim/app/scan_model.py`, `srim/app/runs.py`, `srim/app/plots.py`, `srim/app/scan_plots.py`, `srim/app/recent.py`, `srim/app/export_results.py`. Each task that adds one adds it to the import lines of `tests/test_no_qt.py`. matplotlib is imported only inside functions of the Qt-free plot modules (never at module level), so `tests/test_no_qt.py` also stays free of matplotlib.
- Results the app produces must equal the library's: a single run of a setup gives the same `TRIM.IN` (seed included) as `pysrim2 run` of the saved `run.yaml`; a scan is the `Scan` of the saved `run.yaml` run by `run_scan`.
- The app always runs a saved setup: Start on an unsaved or modified setup saves it first (Save As when it has no path). The run folder is `<setup folder>/<setup stem>-runs/<UTC %Y%m%dT%H%M%SZ>/`, a normal scan folder (`.pysrim2-scan`, `scan.yaml`, `points/`, `result/`).
- While a run is going the setup is locked: `DocumentModel.edit`, undo, redo, New and Open are refused, the editor tabs are disabled. Results remember the document they were made from; once the document differs, the Results tab says "From the previous setup".
- Back end: route `container` → `run_scan(backend="container")`; any other route → `"local"`.
- Tests never run SRIM: runs use fake runners (`run_scan(runner=...)`), module-level functions in `tests/app/runners.py` that return `Results(test_files/1)` (and variants), as in `tests/scan/test_backends.py`. Worker processes start with `spawn`.
- No whole big output is read into memory for a plot: per-ion plots (`collision`, `range3d`, `exyz`, `backscat`, `transmit`, `sputter`) read at most `PLOT_ROW_CAP = 200_000` rows through the library's streaming (`srim.output._chunks`, `Collision.iter_events`) and say "first 200,000 rows" in the title when capped; drawing that can take long runs through `srim/app/workers.py` `run_in_thread`.
- App settings stay in `<data dir>/app/settings.json`; recent runs in `<data dir>/app/recent.json`, written atomically (`_write_json_atomic`); a broken file reads as empty.
- Every user-visible change gets a CHANGELOG line under `## [Unreleased]`; conventional commit prefixes; commit with explicit paths (`git commit -- <paths>`); never `uv run --active`; no AI co-author trailers. Wait for every command you start to finish before reporting.

## Review Focus

1. Stop, pause and Quit during a run: Stop ends the run within a few seconds with the running points `stopped` and no worker, TRIM, `wineserver` or container left behind; Quit during a run asks, then stops the run before closing; Pause lets running units finish and starts none. (Task 5)
2. A run where SRIM fails or some points fail: the Progress tab shows `failed` with the error and "Open log", the Results tab shows the points that finished, the app stays responsive and a new run can start. (Tasks 5, 6, 8)
3. Results that lack outputs or points: a quick run without `RANGE_3D.txt`/`COLLISON.txt`, a scan with failed or stopped points, a scan where every point failed: plots that cannot be drawn are greyed with the reason, nothing raises. (Tasks 7, 8, 9)
4. Huge outputs (a `COLLISON.txt` of gigabytes, a `RANGE_3D.txt` of millions of ions): plots read at most `PLOT_ROW_CAP` rows, are drawn off the GUI thread and say they are capped; the window keeps repainting. (Tasks 7, 8)
5. A scan file written by hand or by the CLI (explicit `points:`, `python:` extractors, a precision target, `batch_ions`, `seed`): opening and saving it without edits keeps both `RunSpec.to_dict()` and `Scan.to_dict()` identical; the Scan tab shows what it cannot edit as read-only text. (Tasks 2 and 3)
