# pysrim2 0.9.0 — Scans, Parallel Runs and Live Progress Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Collision-free concurrent runs, batched runs with recorded seeds, extractors, flexible scans (grid / points, Python or `run.yaml`), a parallel local executor with retries/clean stop, precision targets, a spec-hash cache, container and Slurm backends, a `pysrim2 scan` CLI and terminal-first live views (plot default, dashboard, web, plain/json, Jupyter) — released as 0.9.0.

**Architecture:** New package `srim/scan/` (`spec.py` scan definition, `extract.py` registry + predefined extractors, `batches.py` batching/merging, `executor.py` local pool + backends, `cache.py`, `events.py` event bus, `result.py` ScanResult). Runs become isolated: `srim/rundir.py` creates per-run working copies of the installed SRIM and per-run wine prefixes. UIs in `srim/ui/` consume the event stream (plain/json always; Textual views in extra `[tui]`). The executor never depends on a UI.

**Tech Stack:** Python 3.11–3.15 stdlib (`concurrent.futures`/`multiprocessing`, `fcntl`/`msvcrt` locks), pandas, numpy, optional Textual (+ textual-plotext or equivalent) and textual-serve (`[tui]`), matplotlib (`[plot]`), real-SRIM integration tests (marker `srim`).

**Spec:** `docs/superpowers/specs/2026-11-05-pysrim2-0.9.0-scans-design.md` (binding) and `2026-11-03-pysrim2-design.md`.

## Global Constraints

- Several pysrim2 processes at once must never collide (user decision): runs use private run directories; the installed SRIM dir is never written during a run; each run's wine prefix is private, so failure cleanup (`wineserver -k`) only affects that run; cache/scan writes are atomic and locked.
- Legacy explicit `run(srim_directory=...)` keeps in-place behaviour but under an exclusive file lock.
- Cache key = SHA-256 of the canonical `spec:` YAML (the one that regenerates TRIM.IN) + seed. Any TRIM.IN-affecting field is part of the key.
- Same spec + seed → identical results on the same platform; cross-platform informational.
- No detach/watch features — docs recommend tmux; all terminal views must work over SSH and inside tmux (incremental redraw).
- New optional extra `[tui]` (Textual + plotting add-on + textual-serve); without it `--ui plain` is used automatically. No new required deps.
- UI work never blocks workers (events via a queue; UI drops/coalesces updates if slow).
- Python ≥ 3.11; CHANGELOG line per user-visible change; small commits; CI green (Linux, Windows, container; macOS locally if GitHub stalls).
- `TRIM.run()` default behaviour change (isolated run dir) gets a prominent CHANGELOG "Changed" entry + migration note.
- First step of Task 1: `uv version 0.9.0.dev0`.

## Review Focus

1. Two scans (or a scan + a single run) started at the same time on one machine — no shared files written, distinct correct results, one failing doesn't kill the other's wine. (Tasks 2, 8)
2. Ctrl-C during a 32-worker scan — all SRIM/wine child processes stop, finished points stay in the cache, rerun resumes. (Task 6)
3. A cached result reused for a spec that differs only in a TRIM setting — must NOT happen (key covers all fields). (Task 8)
4. Precision target never reached (noisy quantity) — stops at max ions, reports achieved uncertainty and a warning, not an infinite loop. (Task 7)
5. Disk usage: per-run SRIM copies for 32 workers × many points — hard links / reuse of worker dirs, cleanup on success; no unbounded growth. (Task 2)

- [ ] Unit tests (mocked SRIM): no writes to the installed dir; lock contention; cleanup; disk usage of a run dir (hard links count). Integration (marker srim): 4 concurrent processes (`multiprocessing`) → distinct correct results; induced failure in one run (kill its SRIM) → others unaffected.

### Task 3: Batched runs with recorded seeds
**Files:** `srim/scan/batches.py`; Tests `tests/scan/test_batches.py`
**Interfaces:** `run_batches(spec: RunSpec, n_ions: int, batch_ions: int, seed: int | None, *, run=..., parallel=None) -> MergedResults` — batch i uses seed `derive_seed(seed, i)` (documented deterministic derivation), merges per-ion tables (concat with global ion index) and depth profiles (ion-count-weighted mean); records all seeds; `MergedResults` behaves like `Results` for extractors (same `.df`/`to_dataframes` surface).
- [ ] Tests: merging equals a single run's statistics on synthetic data; seed derivation stable; integration: 2×100 vs 1×200 ions agree statistically.

### Task 4: Extractors

### Task 5: Scan definition and result table

### Task 6: Local parallel executor, events, retries, clean stop
**Files:** `srim/scan/executor.py`, `srim/scan/events.py`; Tests (mocked SRIM + small real-SRIM integration)
**Interfaces:** `run_scan(scan, *, workers=None, backend="local", on_event=None, cache=..., stop_event=None) -> ScanResult`; workers = process pool with one reusable RunDir per worker; events (dataclasses → JSON): `ScanStarted`, `PointQueued/Started/Progress/Finished/Failed/Retried`, `BatchFinished(ions, value_estimates)`, `WorkerStats(cpu, ions_per_s)`, `ScanFinished`; retry once then fail; SIGINT/`stop_event` → stop scheduling, terminate SRIM children cleanly (per-run wineserver -k), keep finished; default workers = cpu_count-1.
- [ ] Tests: retry/fail paths, Ctrl-C simulation (no orphan processes — check with psutil-free stdlib means), events order; integration: 4 points × 2 workers real SRIM.

### Task 7: Precision targets
**Files:** `srim/scan/precision.py`; Tests
**Interfaces:** `Precision(target: str, rel: float | None = None, abs: float | None = None, min_ions=..., max_ions=..., batch_ions=...)`; estimators: SEM across batches for means; bootstrap over per-ion data (or batch jackknife) for straggles; scheduler adds batches until target met or max reached (warning, status `max_ions`); value ± err in table.
- [ ] Tests: synthetic noise converges; never-converging stops at max with warning; deterministic given seed.

### Task 8: Cache and reruns
**Files:** `srim/scan/cache.py`; Tests
