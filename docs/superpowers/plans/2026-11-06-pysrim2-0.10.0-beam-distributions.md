# pysrim2 0.10.0 — Beam Distributions Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Describe the incoming beam (energy, tilt, azimuth, lateral position, start depth) with distributions — fixed, Gaussian, uniform, triangular, log-normal, histogram, Python function — and get one result for the whole beam, in exact mode (sampled ions in `TRIM.DAT`) or binned mode (fixed-value runs per bin through the scan engine), from Python and `run.yaml`; released as 0.10.0.

**Architecture:** New package `srim/beam/` holds the shapes and sampling (`shapes.py`), histogram files (`histfile.py`), the spec parts and validation (`spec.py`), exact mode (`exact.py`: sampling of the ions, `TRIM.DAT` read/write), binned mode (`binned.py`: bins, ion allocation, the fixed spec of a bin), the entry point (`run.py`: `run_beam`, `open_results`) and the overlay (`plot.py`). The distributions live inside `RunSpec` (`IonSpec` fields may hold a shape; new `RunSpec.beam` options), so `--set`, scans, cache and the container back end see them like any spec field. Exact mode is a plain `TRIM` run that also writes `TRIM.DAT`; runs above 99 999 ions and all binned runs go through `run_scan` with a single point, whose units are batches (exact) or bin runs grouped into beam batches (binned), merged with `MergedResults`.

**Tech Stack:** Python ≥ 3.11, numpy (`Generator(PCG64)`, `SeedSequence`), pandas, PyYAML; matplotlib only through the `[plot]` extra; real-SRIM tests with marker `srim`.

**Spec:** `docs/superpowers/specs/2026-11-06-pysrim2-0.10.0-beam-distributions-design.md` (binding, including its "Calls made after the builder check") and `docs/superpowers/specs/notes/2026-11-05-trimdat-spike.md` (binding file format).

## Global Constraints

- Runs without distributions are unchanged: `TRIM.IN` byte-identical, `RunSpec.to_dict()` without new keys, `run.yaml` schema version stays 1, `cache_key` and `spec_hash` values unchanged.
- No new required dependencies; matplotlib imported lazily (`[plot]` extra).
- TRIM.DAT (spike): 10 header lines (line 8 = the run description), one line per ion `Name Z Energy_eV X_depth_A Y_A Z_A cosX cosY cosZ`, CRLF line ends, trailing `0x1A`, at most **99 999** ion lines; TRIM.IN ion count = number of lines; TRIM.IN energy = the maximum energy in the file (keV); cosX > 0; start depth inside the target; single ion species; calculation 4 (quick KP) / 5 (full cascades).
- Exact mode maps the spec's `calculation` 1 → 4 and 2 → 5; any other calculation with a distributed beam in exact mode is a `SpecError`. Binned mode keeps the user's calculation.
- Same spec + seed → same sampled beam and same results on the same platform. Random numbers: `np.random.SeedSequence(seed).spawn(6)`, one `Generator(PCG64)` per parameter, in the fixed order `energy_keV, angle_deg, azimuth_deg, y_nm, z_nm, depth_nm`.
- Cache key and point id cover the distribution definitions, histogram *content* and Python-function *source*; a changed distribution never reuses old runs.
- Validate and refuse (`SpecError`, naming the dotted key) rather than run a beam that differs from the defined one.
- Default mode `exact`; position distributions and a non-uniform azimuth are exact-only; binned mode warns above 200 combined bins and refuses above `max_bins` (default 2 000).
- Conventional commits, one concern per commit; a CHANGELOG line under `## [Unreleased]` per user-visible change; never commit SRIM binaries; fixtures in `test_files/` are byte-exact (CRLF) and not hand-edited.
- Workers start with `spawn`; anything a worker must import (Python-function distributions in exact mode) must be importable by module name.
- First step of Task 1: `uv version 0.10.0.dev0` and set the design doc's status line to `approved 2026-11-06`.

## Review Focus

1. **Messy histogram files** — a CSV exported from a spreadsheet with a header row (`energy_keV,count`), `;` separators, comma decimals, CRLF, blank lines or a trailing empty column must load; a negative count, a non-increasing value column or an all-zero file is a `SpecError` naming the file and line. (Task 2)
2. **Zero-width shapes** — scanning `ion.energy_keV.gaussian.sigma: [0, 2, 5]` must run the `0` point as a monoenergetic beam (a shape of width 0 becomes its fixed value), not fail the scan. (Task 1, Task 3)
3. **Histogram edited in place** — rerunning a scan after changing the numbers in the same histogram file must not hit the cache; changing a Python-function body must not either. (Task 5)
4. **Scanning a shape key that is not there** — `ion.energy_keV.gaussian.sigma=7` on a scalar energy, or on a `uniform` energy, is a `SpecError` that names the key and the shape that is there. (Task 3)
5. **A Python function defined in the user's script** (`__main__`) — exact mode samples in the worker process, which cannot import `__main__`; this must be a clear `SpecError` at validation ("define it in an importable module"), not a worker crash. (Task 3)

### Task 6: Binned mode — bins and ion allocation

**Files:**
- Create: `srim/beam/binned.py`
- Test: `tests/beam/test_binned.py`

**Interfaces:**
- Consumes: `effective`, `BeamOptions` (Task 3); `Shape.equal_probability_edges/probabilities/interval_mean` (Task 1).
- Produces:
  - `AUTO_BINS = {"energy_keV": 10, "angle_deg": 6}`; `WARN_BINS = 200`.
  - `@dataclass(frozen=True) BeamBin(index: int, energy_keV: float, angle_deg: float, probability: float, energy_range: tuple[float, float] | None, angle_range: tuple[float, float] | None)`.
  - `make_bins(spec: RunSpec) -> list[BeamBin]` — per parameter: fixed → one bin at the value (range None); int n → `equal_probability_edges(n)`; list → those edges (probability outside them is dropped and renormalised, `UserWarning` if > 0.1 %); value = `interval_mean`; Cartesian product energy-major; zero-probability combinations dropped; `UserWarning` above `WARN_BINS`, `SpecError` above `spec.beam.max_bins` (message names `beam.max_bins` and the count).
  - `allocate_ions(probabilities, total: int) -> np.ndarray` — Webster/Sainte-Laguë apportionment, ties to the lower index; house-monotone; ≤ 1 s for 10⁷ ions over 2 000 bins.
  - `beam_batch_allocation(probabilities, done: int, size: int) -> np.ndarray` = `allocate_ions(p, done + size) − allocate_ions(p, done)` (never negative).
