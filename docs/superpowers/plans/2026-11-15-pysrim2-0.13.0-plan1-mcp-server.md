# pysrim2 0.13.0 plan 1: the MCP server and headless mode — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `pysrim2 mcp`, an MCP server over stdio that lets any agent set up, run, read and plot SRIM runs headless, with ask-first rules enforced by pysrim2 and an activity log.

**Architecture:** A Qt-free package `srim/mcp/`. The tools are plain Python (`tools.py`) over a `Backend` interface; plan 1 builds the headless backend (`headless.py`, which reuses the app's Qt-free document model `srim.app.model`, `srim.app.scan_model` and `srim.app.runs`), and plan 2 adds the app backend behind the same interface. `server.py` is the only module that imports the MCP SDK; it adapts the tools to FastMCP, asks the user through elicitation, and chooses the backend per call (`choose_backend`, which in plan 1 always returns the headless one). Headless runs are detached processes (`python -m srim.mcp.detached`) that write `events.jsonl` and read `control.jsonl` in their scan folder, so they outlive the agent.

**Tech Stack:** Python 3.11+, the official MCP Python SDK (`mcp`, FastMCP), the existing scan library, matplotlib (Agg) for headless plots.

**Spec:** `docs/superpowers/specs/2026-11-15-pysrim2-0.13.0-agent-mcp-design.md`. Plan 2 (`2026-11-15-pysrim2-0.13.0-plan2-app.md`) builds on this one; both ship together as 0.13.0.

## Global Constraints

- Python 3.11 or newer. Runtime dependencies stay numpy, pyyaml, pandas. The MCP SDK is the new extra `mcp = ["mcp>=1.12"]`; `app` and `all` include it (`"pysrim2[mcp]"` inside them).
- `import srim`, `import srim.cli` and every `srim.mcp` module except `srim.mcp.server` must not import `mcp` (the SDK) or PySide6. Every new Qt-free module goes on the import lines of `tests/test_no_qt.py`.
- No chat panel. No TCP listener. Nothing needs an API key.
- Ask first: a run estimated longer than **30 minutes**, a run wanting more than **half the CPU cores**, deleting or replacing a file the server did not create this session, discarding unsaved work (plan 2), any installer step. Admin installer steps are never run; their commands are returned.
- Default limits live in `AppSettings`: `agent_max_minutes = 30`, `agent_max_core_fraction = 0.5`.
- One-time approval codes: single use, in memory only, expire after 300 s, bound to `action_hash` of the tool, its arguments, the setup content and the resolved workers.
- A plot or table never reads a whole big output: reuse `srim.app.plots` (`PLOT_ROW_CAP`) and `max_rows`.
- `TRIM.IN` of a run the server starts is byte-identical to the one of the same saved `run.yaml` run from a script (a single run keeps its seed through `srim.beam.beam_scan`).
- Capture child output in files, never pipes (AGENTS.md). Detached processes get their own session/process group so the agent's exit does not kill them.
- Tests never start a real agent, real SRIM or a network service. MCP tests use the SDK's in-memory client session. Run tests use the fake runners (`PYSRIM2_SCAN_RUNNER=module:function`, `tests/app/runners.py`).
- Never `uv run --active` / `uv sync --active` (the maintainer's shell has its own `VIRTUAL_ENV`).
- Every user-visible change adds a line under `## [Unreleased]` in `CHANGELOG.md`. Conventional commit prefixes, one concern per commit.

## Review Focus

- **A bad value from the agent** (`ion.energy_keV=forty`, an unknown key, a negative thickness): the tool returns the library's `SpecError` text and the setup is unchanged — pinned in Task 5.
- **The server process dies mid-run:** a new `pysrim2 mcp` finds the run in the setup's run folders and still reads its status and can stop it — pinned in Task 7.
- **An approval code reused, used for other arguments, used after the setup changed, or expired:** refused — pinned in Task 3.
- **SRIM not installed:** `start_run` refuses with the doctor's guidance text and the install plan hint, never a traceback — pinned in Task 10.
- **Relative paths, paths with spaces, and paths outside the working directory** for `open_setup`/`save_setup`: resolved against the server's working directory; a path that would replace an existing file not created this session asks first — pinned in Task 5.

**Interfaces:**
- Produces, in `backend.py`:
  - `class BackendError(Exception)` (message is shown to the agent as is); `class NeedsApp(BackendError)` ("needs the pysrim2 app: open it with pysrim2 app").
  - `class Backend(Protocol)` — the methods below, all taking and returning JSON-able values. Plan 2's app backend implements the same protocol over the socket.
    - `mode: str` ("headless" | "app")
    - `get_setup() -> dict` — `{"path": str | None, "setup": <clean doc: RunSpec.to_dict() layout, plus "scan": section or None>, "problems": [{"text", "blocking"}], "modified": bool}`
    - `set_values(assignments: list[str]) -> dict` — `--set` style `key=value`, applied together (all or none); returns `get_setup()`. Raises `BackendError` with the `SpecError` text.
    - `set_section(name: str, value: Any) -> dict` — `name` one of `"ion"`, `"target"`, `"run"` (the run-settings keys of the spec), `"scan"` (a `scan:` section or `None` to make it a single run); same all-or-none rule.
    - `new_setup() -> dict`, `open_setup(path: str) -> dict`, `save_setup(path: str | None) -> dict`
    - `would_replace(path: str) -> bool` — true when `path` exists and was not written by this backend in this session.
    - `has_unsaved_changes() -> bool`
    - run, results and install methods: Tasks 7–10.
    - `undo() -> dict`, `redo() -> dict` — headless raises `NeedsApp`.
- `HeadlessBackend(cwd: Path, settings: AppSettings | None = None)`; it holds the document as a dict in the app's layout (`srim.app.model.new_document()`, `from_spec`, `clean`, `problems`, `scan_model.scan_from_section`/`section_from_file`) and its path; `open_setup` and `save_setup` follow `DocumentModel.open`/`save` (histogram copies included). ### Task 7: Detached runs that outlive the agent

**Files:**
- Create: `srim/mcp/detached.py`
- Test: `tests/mcp/test_detached.py`

**Interfaces:**
- Consumes: `srim.scan.run_scan`, `srim.scan.Scan.from_yaml`, `srim.scan.events.event_from_dict`, `srim.ui.web.send_request`, `read_requests`, `CONTROL_FILE`, `srim.ui.tui.state.ScanState`.
- Produces:
  - `EVENTS_FILE = "events.jsonl"`, `PID_FILE = "runner.json"` (`{"pid", "started", "workers", "backend"}`), `LOG_FILE = "runner.log"`.
  - `start_detached(folder: Path, workers: int, backend: str = "local", env: dict | None = None) -> int` — runs `[sys.executable, "-m", "srim.mcp.detached", str(folder), "--workers", str(workers), "--backend", backend]` with stdout/stderr to `folder/runner.log`, stdin from `os.devnull`, `start_new_session=True` on POSIX and `CREATE_NEW_PROCESS_GROUP | DETACHED_PROCESS` on Windows; writes `runner.json`; returns the pid. The scan folder must already hold `scan.yaml`.
  - `main(argv: list[str] | None = None) -> int` (the module's entry): runs `run_scan(Scan.from_yaml(folder/"scan.yaml"), workers=…, backend=…, scan_dir=folder, on_event=<append event.to_json() to events.jsonl, flushed>, stop_event=…, pause_event=…)`; a thread polls `control.jsonl` every 0.5 s with `read_requests` and sets/clears the events. The runner uses the scan runner named in `PYSRIM2_SCAN_RUNNER` when set (as the CLI does). Exit code as `pysrim2 scan run`.
  - `run_state(folder: Path) -> dict` — replays `events.jsonl` into a `ScanState` and returns `{"folder", "status": "running" | "paused" | "finished" | "stopped" | "failed" | "crashed", "points_done", "points_total", "ions_done", "ions_total", "errors": [str], "elapsed_s"}`. `"crashed"` when the pid in `runner.json` is gone and no `scan_finished` event was written.
  - `send_control(folder: Path, action: str) -> None` — `action` in `pause`, `resume`, `stop`; `BackendError` for a finished or crashed run.

| method | asks first when |
|---|---|
| `status()`, `get_setup()`, `lookup_element(text)`, `find_material(text)`, `estimate(workers, batch_ions)`, `run_status(folder)`, `list_runs(setup_path)`, `open_run(folder)`, `summary(folder, point)`, `available_plots(folder, point)`, `table(folder, point, key, max_rows)`, `plot(folder, point, key)`, `install_plan(components)` | never |

| `new_setup(confirm_code=None)`, `open_setup(path, confirm_code=None)` | the backend `has_unsaved_changes()` (text: "discard the unsaved changes of <path or 'the new setup'>") |
| `save_setup(path=None, confirm_code=None)`, `export(folder, fmt, dest, include_collision=False, confirm_code=None)` | `would_replace(path)` / a destination file exists that this session did not write |
| `start_run(workers=None, batch_ions=None, confirm_code=None)` | `reasons_to_ask(RunRequest(...), settings)` is not empty |
| `delete_run(folder, confirm_code=None)`, `install_step(component, confirm_code=None)` | always |

  - The ask flow, `_approve(tool, args, text) -> None`: compute `action_hash(tool, args, backend.get_setup()["setup"], workers)`; a valid `confirm_code` passes; else `ask(text)` — `"allowed"` passes, `"denied"`/`"timed out"` raise `BackendError("the user did not allow this: <text>")`; `None` (cannot ask) issues a code and raises `ApprovalNeeded(text, code)` (a `BackendError` subclass) whose message is: `"This needs the user's OK: <text>. Ask the user. If they agree, call <tool> again with the same arguments and confirm_code=\"<code>\" (valid for 5 minutes)."`. The entry records `ask` and `answer`.
  - `start_run` refuses with the doctor's guidance when `status()["srim_ready"]` is false: `BackendError("SRIM is not ready: <first failing check's message>. See install_plan().")`.
