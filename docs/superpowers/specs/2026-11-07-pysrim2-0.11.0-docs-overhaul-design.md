# pysrim2 0.11.0 — docs overhaul and citation: design

Status: written 2026-11-07, builder-checked · builds on 0.10.0 (released 2026-11-06). Replaces the roadmap item "docs overhaul + CITATION.cff/Zenodo DOI" (no Zenodo DOI in this release, see below).

## Intent

The docs on Read the Docs are thorough reference pages, but a newcomer lands on a front page with one image, a paragraph from 2018 and a flat list of 13 links, and the tutorial is the 2018 pysrim one. Nobody has yet been pointed at the docs; 0.11.0 should make them ready for that.

A physicist who has just found pysrim2 should, in their first half hour:

- get a quick overview of what pysrim2 is and adds,
- see examples they can copy,
- see results: plots and screenshots, in an example gallery,
- learn that they can install the pysrim2 agent skill and have an AI agent run SRIM for them. Arun especially wants this route to be visible.

Success is simply that the docs are useful to that person. Arun: "As long as it is useful, not much can go wrong."

## Goals

1. A new front page (layout "A", chosen from mockups):
   - top navigation: Get started · Gallery · Guides · Reference;
   - a one-line headline and one paragraph: what SRIM is and what pysrim2 adds (runs on Windows, Linux and macOS (via the container); every output parsed into tables; parallel, cached parameter scans; beam distributions; plots);
   - two equal cards side by side: **Start in Python** (install commands and a few lines of a first run, linking to a first-simulation page) and **Start with an AI agent** (`pysrim2 install skill` and a real example prompt, linking to the agent guide). The agent route sits next to the Python route, not after it (Arun);
   - a gallery strip of 4–5 thumbnails linking to the gallery page;
   - below: the guides and the reference.
2. A gallery page: each entry is a picture, one sentence on what it shows, and the short code or agent prompt that produced it, so a reader can reproduce it (Arun: yes).
3. Gallery pictures are committed image files. The docs build never runs SRIM (fast everywhere, incl. Read the Docs). One command rebuilds all scripted pictures; it is meant to be run on a Linux machine with SRIM (Arun will log in there, pull, run it and commit — building on macOS through the emulated container is too slow).
4. A "first simulation" page for the Python route that uses the current API (replacing the 2018 tutorial as the entry point).
5. An agent guide that shows the route end to end: install the skill, an example prompt, what the agent does, the result it gets (the material now only in `examples/agents/README.md` on GitHub comes into the docs).
6. The existing reference pages (run spec, dataframes, scans, beam, export, concurrency, container, command line, installation) are kept and regrouped under Guides/Reference, not rewritten. Fix what is broken: the stale API reference (`docs/source/*.rst` lists `srim.core`, is not in the toctree).
7. Citation: a `CITATION.cff` whose preferred citation is the original paper, and a short "Citing" note in the docs and README saying it is the paper about the original pysrim:
   Ostrouchov, C., Zhang, Y., Weber, W. J. (2018). pysrim: Automation, Analysis, and Plotting of SRIM Calculations. *Journal of Open Source Software*, 3(28), 829. https://doi.org/10.21105/joss.00829
8. README: aligned with the new front page (overview, the two routes, citing), so GitHub and PyPI visitors see the same story.

## Non-goals

- No Zenodo DOI and no pysrim2-specific paper in this release (Arun: "stay with the original DOI"). Can come later.
- No rewrite of the reference pages' content beyond fixes and links.
- No new library features. Code changes only where the docs need them (e.g. a script that makes a gallery picture).
- Gallery pictures are not regenerated in CI or on Read the Docs.

## Anti-goals

- A docs build that needs SRIM, wine, Docker or network access to SRIM downloads.
- Gallery code that does not match the picture shown next to it.
- Hiding the agent route behind the Python route.

## Constraints

- Sphinx with the furo theme and MyST Markdown (existing `docs/conf.py`); Read the Docs builds with `fail_on_warning: true`, so `sphinx-build -W` must pass.
- Python 3.11+; runtime dependencies stay numpy, pyyaml, pandas. Docs-only tools go in the `docs` dependency group.
- Existing tests that guard examples keep working: `tests/test_examples.py` (the boron script must stay byte-identical to the skill's copy), `tests/test_notebooks.py`, and the `-m srim` example and notebook runs.
- The 0.8.0+ API is the one shown everywhere (`TRIM(...).run()`, `Results`, `run.yaml`, scans, `run_beam`).
- Repository conventions in `AGENTS.md` (conventional commits, CHANGELOG line per user-visible change, no SRIM binaries or large outputs committed — gallery images must stay small).

## Decided (Arun)

- Layout A for the front page; agent route side by side with the Python route.
- Gallery entries carry the code or prompt that made them.
- Committed images, a rebuild command, run on Linux by Arun; simple and quick docs build over always-fresh pictures.
- Citation points at the original 2018 JOSS paper, with a note; no Zenodo DOI for now.
- The pictures are made on a Linux machine with SRIM, which Arun logs into, pulls, runs the rebuild command on, and commits from ("once we are at that point"). The plan therefore has a hand-over step for Arun before the release.

## More of Claude's calls (from the builder check)

- **Dependencies.** Gallery scripts use the existing `plot` extra (matplotlib) and, for the terminal screenshot, the `tui` extra; the rebuild command is run as `uv run --extra plot --extra tui python docs/gallery/make.py`. Read the Docs does not install them (it never runs the scripts). If a sphinx extension is added for the cards (e.g. `sphinx-design`), it goes in the `docs` group.
- **Rebuild without SRIM.** Entries that only draw existing results may use the committed real-SRIM fixtures in `test_files/` and run anywhere; entries that need a fresh run use real SRIM with small ion counts and fixed seeds. Without SRIM, `make.py` skips the SRIM entries with one clear line each and exits non-zero only if an entry it attempted failed; `make.py --list` shows which entries need SRIM.
- **Tests.** A default (non-`srim`) test checks that every gallery entry on the page has its script and its image, and that the fixture-based scripts run (into a temporary folder, Agg backend). A `-m srim` test runs the SRIM entries into a temporary folder (so CI exercises them on Linux and Windows); no image comparison.
- **Old images.** Every gallery picture is made by its gallery script; the 2018 images in `examples/images` are not shown in the gallery (they may stay where the old notebooks use them). Until Arun's Linux run, the scripted pictures may be generated locally (fixture-based ones directly, SRIM ones in the slow local container if needed) so the docs can be built and reviewed; Arun's run replaces them before the release.
- **Screenshots.** The terminal live views are captured by script: Textual can save an SVG screenshot of the app in headless mode, driven with a fake runner, so they become `make.py` entries. The browser view is optional and, if shown, a by-hand screenshot with a note on how it was taken.
- **Agent example.** The front-page card, the agent guide and the gallery entry use the existing reference case (200 boron ions at 20 keV and 7 degrees into 100 nm Au on Si, seed 12345; about 282 angstrom mean depth), whose numbers the existing tests keep honest. The prompt is a real one from `examples/agents/README.md`; the shown result is produced by the boron script, and the page says so.
- **Navigation.** furo has no top bar, so "Get started · Gallery · Guides · Reference" becomes the sidebar's top-level sections plus a row of links on the front page; no theme template override.
- **API reference.** Regenerated autodoc pages for the public modules, in the toctree under Reference. Fixing library docstrings so `-W` passes is in scope (docstring text only, no behaviour change).
- **README.** Shortened to the overview, the two routes, a few gallery thumbnails with absolute `https://raw.githubusercontent.com/FSIBT/pysrim2/main/...` URLs (PyPI needs them), citing, and links to the docs.
