# pysrim2 0.10.0: beam distributions (design)

Status: draft for review · 2026-11-06 · builds on 0.9.0 (scans, executor, cache, MergedResults, extractors, `run.yaml`/`RunSpec`) and the TRIM.DAT spike (`docs/superpowers/specs/notes/2026-11-05-trimdat-spike.md`).

## Why

Real beams are not monoenergetic pencil beams: they have an energy spread, a divergence and a spot size, and sometimes only a measured spectrum is known. SRIM's own input describes one energy, one angle and one entry point. 0.10.0 lets users describe the incoming beam with distributions and get one result for that beam, without writing SRIM input files by hand. The idea came from a co-worker of Arun's.

## Goals

1. **A distributed beam is one beam.** A run with a distributed beam returns one result — the usual `Results` / run folder — as if the whole beam had hit the target. Per-ion tables, depth profiles, extractors, export and scans work on it unchanged. Separate results per energy or angle are a parameter scan (0.9.0), not this feature.
2. **Distributable parameters** (independent of each other; correlated/joint distributions are a non-goal for now):
   - **energy**;
   - **angle**: the tilt from the surface normal (today's SRIM angle) and the azimuth around the normal (default: uniform over 0–360°);
   - **position** (exact mode only): the beam spot on the surface in the two lateral directions, and optionally a starting depth below the surface.
3. **Shapes**, available for every parameter: fixed (today's behaviour), Gaussian (mean, width), uniform (min, max), a Python function (probability density over the value), and a measured histogram loaded from a file; plus other common shapes (*Claude's call:* triangular and log-normal). Every shape can be truncated to a range (e.g. no negative energies).
4. **Two modes, both implemented and documented** (decided by Arun):
   - **exact**: pysrim2 samples every ion's energy, direction and start position from the distributions and writes them into SRIM's `TRIM.DAT` (calculation types 4/5, per the spike), so SRIM runs exactly that beam. Runs above SRIM's limit of 99 999 ions per file are split into batches and merged into one result (0.9.0 `MergedResults`).
   - **binned**: the distributions are cut into bins; each bin (or combination of energy and angle bins) runs as a normal SRIM run with fixed values through the 0.9.0 scan engine (parallel workers, cache, precision targets); the bins are combined with their weights into one result. Users choose the bins (number of bins or explicit edges per parameter) **or** let pysrim2 choose them automatically and override if they want (decided by Arun: both).
   - Position distributions are exact-mode only; asking for them in binned mode is a clear error that points to exact mode.
5. **Description in `run.yaml` and Python.** A distribution can stand wherever a fixed beam value stands today, in YAML (a `beam:` / distribution form of `ion.energy_keV`, `ion.angle_deg`, new azimuth and position fields — exact schema left to the builder) and in Python (e.g. `ion.energy_keV = Gaussian(mean=100, sigma=5)`). Python functions are referenced as `python:<module>:<name>` like 0.9.0 extractors; histogram files are copied into the run folder and referenced by relative path, so a run can be repeated anywhere. The mode (`exact` / `binned`) and binning options are part of the spec.
6. **Reproducible.** Sampling uses the run's seed: the same spec and seed give the same sampled beam and the same results on the same platform. The cache key (0.9.0) covers the distribution definitions, including the content of histogram files and the binning, so a changed distribution never reuses old runs.
7. **Checkable.** The sampled values of every ion (exact mode) are saved in the run folder, so the sampled beam can be compared with the distribution; binned runs record their bins and weights. *(Claude's call: a small helper/plot that overlays the sampled values on the defined distribution, also used later by the 0.12.0 beam tab.)*
8. **Scans over distributions.** Distribution parameters are scannable like any spec field (e.g. scanning the energy width), using the existing dotted keys.
9. **Docs**: a page explaining both modes, when to use which (exact: most faithful, the only one with position distributions; binned: faster for large runs, reuses the cache, no ion-count limit), with examples in Python and YAML, an example script and a notebook.

## Non-goals

- Correlated / joint distributions (e.g. angle depending on energy, 2D histograms) — later.
- Mixed ion species in one beam (pysrim2's model has one ion; the spike did not test mixed species).
- Using `TRIM.DAT` as a recoil source (SRIM calculation types 6/7: neutron/electron/photon sources).
- Separate result files per part of the distribution (that is a parameter scan).

## Anti-goals

- A distributed run whose results silently differ from the defined beam (e.g. TRIM.IN header energy below the maximum sampled energy, unnormalised direction cosines, ions starting deeper than the target) — validate and refuse instead.
- Exact and binned mode disagreeing beyond statistics for the same distribution.
- A cache hit for a different distribution, histogram content or binning.

## Constraints

- From the spike (binding): TRIM.DAT has 10 header lines (line 8 becomes the run description), one line per ion `Name Z Energy_eV X_depth_A Y_A Z_A cosX cosY cosZ`, CRLF line ends and a trailing 0x1A; at most 99 999 lines; TRIM.IN's number of ions equals the number of lines and its ion energy is the maximum sampled energy (keV); TRIM.IN's angle is ignored; cosX > 0 points into the target; start depth must be inside the target; single ion species (Z and mass from TRIM.IN); calculation 4 = quick Kinchin-Pease, 5 = full cascades.
- `TRIM.IN` and outputs keep their byte-identical behaviour for runs without distributions (0.8.0 rule).
- Python ≥ 3.11; no new required dependencies (numpy is enough for sampling).

## Decided by Arun

- Both modes, implemented and documented.
- One beam → one result; per-part results are a parameter scan.
- Energy and angle uncorrelated for now; beam position added as a distributable parameter.
- Shapes: Gaussian, uniform and the other common ones, Python functions, measured histograms.
- Binned mode: user-chosen bins and automatic bins, both.
- Keep it general (no assumptions about energy or angle ranges).

## Calls made after the builder check (Claude's, marked as such)

- **Binned mode is one beam with equal-weight ions:** the whole beam's `ions` are split over the bins in proportion to each bin's probability (largest-remainder rounding; *option* `min_ions_per_bin` to give thin tails some ions, then those ions carry a weight column and profiles use weights). By default every ion carries the same weight, so per-ion tables concatenate (with `bin` and the representative values as columns) and profiles combine as the ion-count-weighted mean, exactly like 0.9.0 `MergedResults`; extractors and export work unchanged. Collision/EXYZ are streamed/concatenated as in 0.9.0. *(Claude's call)*
- **Precision targets apply to the whole beam**, not per bin: batches are added across all bins in proportion to their probabilities until the beam's value reaches the target (the 0.9.0 batch-means estimator over beam-level batches). *(Claude's call)*
- **Bins:** per-parameter bins combine as a Cartesian product; pysrim2 warns above 200 combined bins and refuses above 2 000 (override with an option). Automatic binning: equal-probability bins, default 10 for energy and 6 for tilt; azimuth is not binned (SRIM's TRIM.IN has no azimuth; for a laterally uniform target azimuth does not change depth results) — a non-uniform azimuth requires exact mode (clear error otherwise), like position. Each bin runs at its probability-weighted mean value. *(Claude's call)*
- **Agreement test:** a real-SRIM test (`-m srim`, small: ~500 ions) checks that exact and binned mode give the same mean depth within 3 standard errors for a Gaussian energy spread; unit tests check sampling and weighting statistically with fixed seeds. *(Claude's call)*
- **Unbounded shapes and TRIM.IN energy:** Gaussian/log-normal/function shapes are truncated by default at a finite range (Gaussian: mean ± 5 σ; functions and histograms: their given support); exact mode writes the maximum sampled energy into TRIM.IN (deterministic given the seed, so cache-safe). Negative energies or angles outside 0–90° tilt are always cut. *(Claude's call)*
- **Exact-mode batches:** each batch samples from its own derived seed (`derive_seed(seed, batch)`), writes its own TRIM.DAT with as many lines as TRIM.IN's ion count (≤ 99 999), and the batches merge via `MergedResults`; "same seed, same result" holds for a fixed batch layout (as in 0.9.0 `batch_ions`). *(Claude's call)*
- **Calculation type:** a distributed run in exact mode needs quick (Kinchin-Pease) or full cascades and maps them to SRIM types 4/5; the other calculation types with a distributed beam are refused with a clear error (no silent change). Binned mode keeps the user's calculation type. *(Claude's call)*
- **Schema:** additive, `run.yaml` schema version stays 1 for runs without distributions (their TRIM.IN byte-identical); a fixed scalar (`energy_keV: 100`) stays valid; a distribution is a mapping in the same place (`energy_keV: {gaussian: {mean: 100, sigma: 5}}`); new fields `ion.azimuth_deg` and `ion.position` (exact only); `beam_mode: exact|binned` plus binning options under one `beam:` key. Scanning works on the numeric parameters of a shape (`ion.energy_keV.gaussian.sigma`); histogram files are scanned by file path. *(Claude's call)*
- **Python-function distributions:** referenced as `python:<module>:<name>` with a required `range: [min, max]`; sampled by inverse CDF on a fine grid; the cache key includes the function's source code (`inspect.getsource`), so editing it invalidates cached runs. *(Claude's call)*
- **Position convention:** SRIM's lateral Y/Z in nm in the spec (Å in TRIM.DAT); the starting depth is validated against the target's total thickness before running. *(Claude's call)*
- **Sampled-beam record:** exact mode keeps `TRIM.DAT` in the run folder (it is the record) and reads it back lazily for the overlay; no separate copy. *(Claude's call)*
- **Histogram files:** two columns (`value, count`) where the values are bin centres, or three columns (`low, high, count`); comma-decimal and CRLF accepted (0.8.0 parsing rules); sampled as piecewise-constant density (uniform within a bin). *(Claude's call)*
- **Random numbers:** numpy `Generator(PCG64)` with one independent stream per parameter (spawned from the run seed), so adding a position distribution does not change the sampled energies. *(Claude's call)*
- **Overlay helper:** `srim.beam.plot_beam(results)` (matplotlib from the `[plot]` extra); shape classes importable from `srim.beam` (`Gaussian`, `Uniform`, `Triangular`, `LogNormal`, `Histogram`, `Function`, `Fixed`). *(Claude's call)*

## Left to the builder (Claude's calls)

- Exact YAML schema and Python class names; histogram file formats (at least two-column text/CSV of bin edges or centres and counts) and normalisation.
- Automatic binning rule (e.g. equal-probability bins, default count) and how bins of several parameters combine; how binned results are weighted and merged (per-ion tables with a bin column, profiles as weighted sums), incl. precision targets per bin vs for the whole beam.
- Default mode when the user doesn't choose (*suggestion:* exact up to the batch limit, then still exact with batches; binned only on request).
- Sampling algorithm (inverse CDF for histograms and Python functions on a grid), handling of truncation, azimuth default, position coordinate convention (SRIM's Y/Z), starting-depth validation.
- How the sampled-beam record is stored (Parquet/CSV in the run folder) and the overlay helper.
